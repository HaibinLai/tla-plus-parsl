# Clock, heartbeat, and timeout

This file contains the complete ledger entries assigned to this component. See the [split index](../index.md) or the [flat compatibility ledger](../../bug-ledger.md).

| ID | Component | Current behavior / risk | Evidence | Candidate safety condition | Status |
| --- | --- | --- | --- | --- | --- |
| BUG-026 | HTEX heartbeat expiry | `Interchange.expire_bad_managers` compares wall-clock timestamps from `time.time()` with a heartbeat threshold. A forward system-clock jump can expire a healthy manager prematurely; a backward jump can defer expiry. | `ParslHeartbeatClockJumpCurrent.cfg` (4 generated/3 distinct, `NoPrematureExpiry` counterexample); fixed 6 generated/3 distinct; `tests/test_heartbeat_clock_jump_runtime.py` | Measure heartbeat age with a monotonic clock or otherwise make expiry robust to wall-clock adjustments. | Reproduced in model and runtime probe; candidate fixed model passes; source fix pending |
| BUG-087 | Expired command deadline forwards negative ZMQ poll timeout | `CommandClient.run` computes remaining time after the deadline and passes a negative millisecond value directly to `zmq.Socket.poll`; the current runtime probe observes the negative timeout instead of an immediate zero-timeout decision. | `ParslCommandDeadlineCurrent.cfg` (2-state `PollTimeoutSafety` counterexample); fixed 4 generated/2 distinct; `tests/test_command_deadline_runtime.py::test_expired_deadline_passes_negative_poll_timeout_currently` | Clamp remaining poll time to zero and raise the command timeout without relying on ZMQ's negative-timeout semantics. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-089 | HTEX heartbeat expiry uses adjustable wall clock | `Interchange.expire_bad_managers` computes `time.time() - last_heartbeat`. If the system clock moves backward, an already overdue manager obtains a negative age and remains registered, delaying task-loss detection until wall time catches up. | `ParslHeartbeatClockRollbackCurrent.cfg` (rollback configuration violates `HorizonRequiresExpiry`); fixed model uses monotonic age; `tests/test_heartbeat_clock_jump_runtime.py::test_backward_wall_clock_jump_delays_expiry_currently` | Record a monotonic heartbeat timestamp and use monotonic elapsed time for expiry decisions; keep wall time only for reporting. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-090 | Monitoring batch deadline uses adjustable wall clock | `DatabaseManager._get_messages_in_batch` measures its batching interval with `time.time()`. A backward clock step makes elapsed time negative, so the collector can consume messages beyond the configured batch deadline. | `ParslMonitoringBatchClockCurrent.cfg` (rollback configuration violates `NoOverdueBatch`); fixed model uses monotonic time; `tests/test_monitoring_batch_clock_runtime.py::test_wall_clock_rollback_allows_batch_past_deadline_currently` | Use `time.monotonic()` for batching deadlines and retain wall-clock timestamps only for persisted/reporting data. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-107 | HTEX accepts nonpositive heartbeat parameters | `HighThroughputExecutor` stores `heartbeat_period=0` and `heartbeat_threshold<0` without validation. The values later feed heartbeat polling/expiry logic and can disable or distort liveness detection instead of failing configuration early. | `ParslHeartbeatParameterValidationCurrent.cfg` (2-state `ParameterSafety` counterexample); fixed and valid configurations pass; `tests/test_heartbeat_parameter_validation_runtime.py::test_constructor_accepts_nonpositive_heartbeat_values_currently` | Require strictly positive heartbeat period and threshold during executor construction. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-108 | Python app negative timeout injects immediate failure | The `timeout` decorator passes a negative delay directly to `threading.Timer`. Calling the wrapped function therefore raises `AppTimeout` immediately rather than rejecting the invalid parameter during wrapper construction. | `ParslPythonTimeoutParameterCurrent.cfg` (2-state `TimeoutParameterSafety` counterexample); fixed and valid configurations pass; `tests/test_python_timeout_parameter_runtime.py::test_negative_timeout_injects_immediate_app_timeout_currently` | Validate timeout values at decoration/configuration time and require a strictly positive delay. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-114 | HTEX zero address-probe timeout is silently dropped | `HighThroughputExecutor.initialize_scaling` uses a truthiness check when rendering `address_probe_timeout`. An explicit zero is omitted from the worker command, so the worker silently uses its own default rather than the configured value. | `ParslHtexAddressProbeTimeoutCurrent.cfg` (2-state `TimeoutPropagationSafety` counterexample); fixed and valid configurations pass; `tests/test_htex_address_probe_timeout_runtime.py::test_explicit_zero_is_dropped_from_worker_command_currently` | Preserve explicit zero/validate it deliberately, and make the worker-side timeout contract explicit instead of silently substituting a default. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-118 | Provider polling suppressed after wall-clock rollback | `BlockProviderExecutor.poll_facade` schedules polls with `time.time()` and retains the pre-rollback `_last_poll_time`. If the system clock moves backward, a poll that is due in monotonic time is skipped until wall time catches up. | `ParslProviderPollClockRollbackCurrent.cfg` (2-state `RollbackPollSafety` counterexample); fixed model passes; `tests/test_provider_poll_clock_rollback_runtime.py::test_backward_wall_clock_jump_suppresses_due_poll_currently` | Use a monotonic clock for polling intervals or reset the baseline when the wall clock moves backward. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-120 | Positive sub-minute walltime truncates to zero | `wtime_to_minutes` truncates the seconds component. A positive duration such as `00:00:59` becomes zero scheduler minutes, potentially producing an immediately-expiring or invalid job request. | `ParslWalltimeParsingCurrent.cfg` (2-state `PositiveDurationSafety` counterexample); fixed and valid configurations pass; `tests/test_walltime_parsing_runtime.py::test_subminute_walltime_is_truncated_to_zero_minutes_currently` | Round positive sub-minute durations up to one minute (or reject them explicitly) before provider submission. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-122 | Poller close scales in while callback thread is alive | `JobStatusPoller.close(timeout)` proceeds to executor scale-in after a timed-out thread join. A still-running status callback can therefore overlap provider scale-in and race on block/resource state. | `ParslPollerCloseScaleInRaceCurrent.cfg` (5-state `ScaleInAfterPollQuiescence` counterexample); fixed model passes; `tests/test_poller_close_scale_in_runtime.py::test_current_close_scales_in_while_timer_thread_is_alive` | Do not scale in until the poll callback is quiescent, or make timeout closure explicitly defer scale-in until thread termination. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-128 | Timer close reports completion before callback quiescence | `Timer.close(timeout=...)` returns `None` after a timed thread join even though the callback thread is still alive. Callers can interpret the return as a completed close and race with callback activity. | `ParslTimerCloseTimeoutCurrent.cfg` (2-state `CloseQuiescenceSafety` counterexample); fixed configuration passes with 3 distinct states; `tests/test_timer_close_timeout_runtime.py::test_close_timeout_returns_while_callback_thread_is_alive` | Return an explicit timeout/closing outcome or otherwise expose that the timer remains active until the callback exits. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-132 | `execute_wait` timeout leaves process group alive | `parsl.utils.execute_wait` creates a new process group but re-raises `TimeoutExpired` without terminating the process or group. A timed-out scheduler command can therefore continue running after the caller has observed failure. | `ParslExecuteWaitTimeoutCurrent.cfg` (2-state `TimeoutCleanupSafety` counterexample); fixed configuration passes with 2 distinct states; `tests/test_execute_wait_timeout_runtime.py::test_timeout_reraises_without_terminating_process_currently` | Kill/terminate the process group on timeout, reap the process, and then report the timeout. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-133 | Bash app timeout leaves shell process alive | `remote_side_bash_executor` raises `AppTimeout` when `Popen.wait(timeout=...)` expires but does not kill or reap the shell/process group. A timed-out Bash app can continue running after the AppFuture reports failure. | `ParslBashTimeoutCleanupCurrent.cfg` (2-state `TimeoutCleanupSafety` counterexample); fixed configuration passes with 2 distinct states; `tests/test_bash_timeout_cleanup_runtime.py::test_timeout_raises_without_killing_current_shell` | Terminate the shell/process group, reap it, and only then propagate `AppTimeout`. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-134 | `time_limited_open` exposes raw missing-file error after timeout | When the polling horizon expires without the path appearing, `time_limited_open` still calls `open()` and raises `FileNotFoundError` instead of returning an explicit timeout outcome. Callers cannot distinguish a wait timeout from an ordinary open failure. | `ParslTimeLimitedOpenTimeoutCurrent.cfg` (2-state `MissingFileSafety` counterexample); fixed configuration passes with 2 distinct states; `tests/test_time_limited_open_timeout_runtime.py::test_missing_file_exposes_raw_open_error_after_wait_currently` | Check the polling deadline before opening and raise a dedicated timeout error or return a documented timeout result. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-137 | HTEX worker contact timeout is suppressed by wall-clock rollback | `Manager.interchange_communicator` stores `last_interchange_contact` with `time.time()` and compares later `time.time()` readings. A backward system-clock step can keep the apparent age below `heartbeat_threshold`, leaving a worker alive after the elapsed contact deadline. | `ParslWorkerContactClockRollbackCurrent.cfg` (4 distinct states, `HorizonRequiresStop` counterexample); fixed configuration passes with 4 distinct states; `tests/test_worker_contact_clock_rollback_runtime.py::test_wall_clock_rollback_suppresses_worker_expiry_currently` | Use a monotonic clock for contact-age expiry, while retaining wall time only for human-readable timestamps. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-148 | Globus ACTIVE transfer has no overall timeout | `Globus.transfer_file` passes a 60-second timeout to each `task_wait` call but repeats the loop indefinitely while the service reports `ACTIVE`. | BUG-162 | Resource monitor wall-clock rollback suppresses due sample | `parsl.monitoring.remote.monitor` schedules periodic resource messages with `time.time()`. After a backward wall-clock step, `next_send - time.time()` becomes positive even when elapsed time has reached the sampling horizon, delaying the intermediate sample. | `ParslResourceMonitorClockCurrent.cfg` (3-state `NoDueSuppression` counterexample); fixed configuration passes; `tests/test_resource_monitor_clock_runtime.py::test_wall_clock_rollback_suppresses_due_intermediate_sample_currently` | Use a monotonic scheduling clock for sampling deadlines and retain wall time only for persisted timestamps. | Reproduced with a source-level fake monitor/radio; candidate fixed model passes |
| BUG-218 | HTEX contact timeout starved by result traffic | `Manager.interchange_communicator` checks the contact deadline only when neither the interchange socket nor the result socket is readable.
