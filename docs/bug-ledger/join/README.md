# join_app and memoization

This file contains the complete ledger entries assigned to this component. See the [split index](../index.md) or the [flat compatibility ledger](../../bug-ledger.md).

| ID | Component | Current behavior / risk | Evidence | Candidate safety condition | Status |
| --- | --- | --- | --- | --- | --- |
| BUG-008 | `join_app` list semantics | Treating a list of inner Futures as a set loses duplicate positions and can change the outer result shape. | `ParslJoinComplete.tla`; `tests/test_join_retry_duplicates_runtime.py` | Preserve ordered list positions, including duplicate Future references. | Reproduced; candidate fixed model passes |
| BUG-011 | `join_app` cancellation | `Future.exception()` raises `CancelledError` for a cancelled single inner Future; `handle_join_update` lets it escape and leaves the outer task in `joining`. | `ParslJoinSingleCancellation.tla` and `ParslJoinCancellation.tla` (current counterexamples); direct and end-to-end probes in `tests/test_join_single_cancellation_runtime.py` and `tests/test_join_cancellation_end_to_end_runtime.py` | Inner cancellation must become terminal outer join failure (or an explicit cancellation state). | Reproduced in direct and real decorated single-Future `join_app` paths; candidate fixed model passes |
| BUG-012 | `join_app` retry/cancellation | After an inner non-final attempt fails and enters retry, cancellation of that inner Future reaches the same callback escape path; the other completed inner Future cannot finalize the outer join. | `ParslJoinRetryCancellation.tla` (30-state current counterexample, 1,372 generated/484 distinct fixed), `ParslJoinListCancellation.tla`, and list/single cancellation probes including `tests/test_join_list_cancellation_end_to_end_runtime.py` | Retry state must not change cancellation into a non-terminal callback exception; outer join must terminate deterministically. | Reproduced in direct and real decorated list-valued paths; candidate fixed model passes |
| BUG-036 | `join_app` mutable-list snapshot | The DFK stores the mutable list returned by a join app directly in `task_record['joins']`. Mutating that list before callbacks run changes the outer result shape, potentially dropping inner Futures without an error. | `ParslJoinListMutationCurrent.cfg` (4 generated/3 distinct, `JoinSnapshotSafety` counterexample); fixed 6 generated/3 distinct; stable/no-mutation 4 generated/2 distinct; `tests/test_join_list_mutation_runtime.py` | Snapshot join-list membership when entering `joining`, or otherwise reject mutations after registration. | Reproduced in model and runtime probe; candidate fixed model passes |
| BUG-084 | `join_app` return validation invokes user equality | Invalid returns can raise from `__eq__` or spoof equality with `[]`, bypassing type validation and leaving the outer Future pending. | `ParslJoinReturnEqualityCurrent.cfg`, `ParslJoinReturnEqualityTruthyCurrent.cfg`; `tests/test_join_return_equality_runtime.py` | Validate Future/list type before equality and convert invalid returns to terminal `TypeError`. | Reproduced; candidate fixed models pass |
| BUG-178 | Immediate cancelled join callback leaves outer Future joining | If an inner Future is already cancelled when `join_app` registers its callback, `add_done_callback` invokes `handle_join_update` synchronously. `Future.exception()` raises `CancelledError` inside that callback; the callback framework logs the escape and the outer task remains in `joining` without a terminal result. | `ParslJoinImmediateCancellationCurrent.cfg` (2-state `ImmediateCancellationSafety` counterexample); fixed configuration passes; `tests/test_join_single_cancellation_runtime.py::JoinSingleCancellationRuntimeTest::test_already_cancelled_inner_immediate_callback_leaves_outer_joining_currently` | Convert cancellation from an immediate callback into a terminal outer failure before returning from callback registration. | Reproduced against the installed DataFlowKernel; candidate fixed model passes |
| BUG-231 | Outer join Future cancellation is not implemented | `AppFuture.cancel()` raises `NotImplementedError` for an outer `join_app` Future, so callers cannot terminate a joining outer task and the Future remains pending. | `ParslJoinFullCurrent.cfg` (`CancellationSupportSafety` counterexample); `tests/test_outer_join_cancellation_runtime.py` | Implement terminal outer cancellation, cancel or detach inner callbacks, and persist a deterministic cancellation/JoinError state. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-237 | DFK cleanup returns before outer join quiescence | `DataFlowKernel.cleanup()` closes components and publishes workflow completion without waiting for outer join tasks still in `joining`. A later inner callback can therefore complete and mutate the outer task after cleanup has returned. | `ParslJoinCleanupLifecycleCurrent.cfg` (counterexample to `JoinQuiescence`/`TerminalCountSafety`); fixed configuration passes; `tests/test_join_cleanup_lifecycle_runtime.py` | Wait for joining tasks to become terminal before workflow end, or explicitly fail/detach them as part of cleanup. | Reproduced against the installed DataFlowKernel; candidate fixed model passes |
| BUG-245 | DFK checkpoint serialization failure strands successful Future | `_complete_task_result` writes a task-exit checkpoint before updating task state or resolving the AppFuture. An unpickleable successful result raises from checkpoint writing, leaving the logical task running and its Future unresolved. | `ParslMemoCheckpointResultFailureCurrent.cfg` (counterexample to `CheckpointFailureTerminality`); fixed configuration passes; `tests/test_memo_checkpoint_result_failure_runtime.py` | Convert checkpoint-write failure into an explicit terminal outcome, or resolve the task independently of optional checkpoint persistence. | Reproduced against the installed DataFlowKernel/BasicMemoizer; candidate fixed model passes |
