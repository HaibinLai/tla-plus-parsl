| BUG-088 | Failure fan-out mutates task dictionary during iteration | `BlockProviderExecutor.set_bad_state_and_fail_all` iterates `self._tasks` while `Future.set_exception` synchronously runs callbacks. A callback that removes its task entry raises `RuntimeError: dictionary changed size during iteration`, so executor failure handling can stop before all tasks are failed. | `ParslBadStateTaskMutationCurrent.cfg` (2-state `MutationSafety` counterexample); fixed 6 generated/3 distinct; `tests/test_bad_state_task_mutation_runtime.py::test_callback_removing_task_breaks_current_failure_fanout` | Snapshot task entries before completing Futures, or otherwise make failure fan-out mutation-safe. | Reproduced against the installed Parsl source; candidate fixed model passes |
| BUG-259 | DataFlowKernel duplicates `inputs` dependencies | `_gather_all_deps` traverses every kwarg and then traverses `kwargs['inputs']` again in its dedicated inputs pass. A Future supplied only through `inputs` is stored twice; when the same Future also appears in a normal kwarg, the current path stores it three times and registers duplicate callbacks. | `ParslInputDependencyDuplicateCurrent.cfg` and `ParslDependencyIdentityDedupCurrent.cfg` (counterexamples to `NoDuplicateDependency`); fixed configurations pass; `tests/test_input_dependency_duplicate_runtime.py` | Exclude reserved `inputs` from the generic pass and de-duplicate dependency identities globally before callback registration. | Reproduced against the installed DataFlowKernel; candidate fixed models pass |
