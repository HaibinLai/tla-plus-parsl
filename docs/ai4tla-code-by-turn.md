# Code Changes by AI Turn

The daily analysis hides autonomous bursts inside a date. This companion
analysis maps each Git code change to the nearest classified AI turn by
timestamp. It therefore shows how much code was changed around turn N, while
keeping the attribution explicitly temporal rather than causal.

## Results

- 1,779 classified turns
- 1,973 mapped commits
- 1,411 turns with at least one mapped code addition
- 369 turns with no mapped code addition
- median: 26 code lines added per turn
- mean: 60.341 code lines added per turn
- median commits per code-changing turn: 1
- largest turn: 5,809 code lines, caused by a large cross-component model commit

The largest turn is an outlier. It is more informative to inspect the
distribution and the number of zero-change turns than to use the mean alone.
Many turns are analysis, test execution, or coordination turns; they should
not be expected to modify files.

The visualization is `site/dist/code-by-turn.svg`:

- x-axis: classified AI turn number;
- y-axis: code lines added in commits nearest to that turn;
- y-axis uses a log transform so small changes and large model-generation
  bursts are both visible;
- color identifies the dominant phase of the turn;
- hovering a bar shows turn number, additions, commit count, phase, and time.

The underlying mapping is in `docs/ai4tla-code-by-turn.json`, generated by
`scripts/analyze_code_by_turn.py`.

For an unaggregated view, `site/dist/code-by-commit.svg` plots every mapped
commit separately. Its x-axis is chronological commit number, its y-axis is
the number of code lines added by that commit, and hover text includes the
commit hash, subject, nearest turn, timestamp, and phase.

For a reader-oriented trend view, use `site/dist/code-trend-human.svg`. It
groups commits into chronological windows, draws the median and interquartile
range, calls out the overall statistics, and adds a separate cumulative-size
strip. This view is intended for a report or presentation; the per-commit and
per-turn SVGs remain available for detailed inspection.

## Interpretation

This view supports the idea that “AI coding output” is bursty rather than
smoothly proportional to project size. A complex project produces many turns
with no code change, interleaved with occasional large model additions or
multi-commit repair bursts. That pattern is more consistent with a changing
work mix than with a simple monotonic decline in capability.
