# TLA+ Parsl v0.1 Validation Report

This report is the bounded handoff for the first Parsl abstraction. It is intentionally a
small executable model suite, not a line-by-line reimplementation of Parsl and not a proof that
the implementation is bug-free.

## Acceptance evidence

The current foundational gates pass against the pinned Parsl source and the local TLC toolchain:

- TLC foundational smoke: 678 bounded configurations pass.
- Python runtime foundational smoke: 443 probe entries pass (702 unittest methods are present in
  the repository-wide runtime discovery set).
- Current configurations are retained when they reproduce an observed implementation behavior;
  Fixed configurations encode the candidate safety semantics and are the configurations included
  in the normal regression gate.

Run the gates from the repository root:

```bash
JAVA_BIN=$(find /tmp -path '*/jdk-*/bin/java' -type f -perm -u+x -print -quit)
TLA_JAR=$(find /tmp -path '*/tla2tools.jar' -type f -print -quit)
JAVA_BIN="$JAVA_BIN" TLA_JAR="$TLA_JAR" TLC_SIMULATE=100 \
  bash scripts/tlc_foundational_smoke.sh

PYTHONPATH=/tmp/parsl-source PYTHON_BIN=/tmp/parsl-venv/bin/python \
  PARSL_SOURCE=/tmp/parsl-source bash scripts/runtime_foundational_smoke.sh
```

## Component mapping

| Parsl boundary | TLA+ abstraction | Evidence |
| --- | --- | --- |
| Logical task, physical attempt, dependency blocking | `models/core/ParslAbstract.tla`, `ParslResultRace.tla`, `ParslResultDecodeRetryMonitoring.tla`, pipeline and retry models | end-to-end and dependency probes; bounded decode/retry/late-result/monitoring composition |
| Future/result propagation and `join_app` | `models/dataflow/`, `models/core/ParslJoin*.tla` | join, nested-join, cancellation, duplicate, and failure-aggregation probes |
| Callable/object snapshot and retry transport | `models/serialization/ParslFunctionObject*.tla`, callable cache/snapshot models | dill/serializer and ZMQ runtime probes |
| ZMQ multipart messages and serializer frames | `models/serialization/ParslZMQ*.tla`, `ParslTaskTransport.tla` | frame-count, correlation, ACK, malformed-frame, and transport probes |
| File bytes, checksums, staging and publication | `models/staging/ParslFileBytes.tla`, transfer/version and DataFuture models | Zip, HTTP, FTP, Rsync, Globus, and byte/checksum probes |
| Wall clock, heartbeat, timeout and retry timing | `models/clock/` | rollback, deadline, heartbeat, drain and timer probes |
| Monitoring queue, database and persistence | `models/monitoring/`, monitoring join models | SQLite, queue, UDP/ZMQ, lifecycle and retry probes |
| Executors and workers | `models/executors/` | HTEX, Thread, Flux, MPI, Work Queue, TaskVine and Radical-Pilot probes |
| Providers and resource lifecycle | `models/providers/` and provider bridge models | Local, cluster scheduler, cloud, Kubernetes and Globus Compute probes |

The models separate logical task identity from physical attempt identity wherever a retry or late
result can otherwise resolve the wrong Future. File models similarly separate source bytes,
in-flight bytes, temporary buffers and atomically published bytes.

## Invariants and failure scenarios

Representative safety checks include dependency safety, retry-budget bounds, attempt/result
correlation, terminal-state stability, stale-result rejection, checksum validation, atomic
publication, DataFuture readiness, heartbeat expiry, provider admission, monitoring bookkeeping,
and ordered/duplicate `join_app` aggregation.

The bug ledger records concrete implementation observations separately from candidate fixes. It
contains source locations, a runtime probe where feasible, and a Current/Fixed model pair for
serialization, staging, clocks, monitoring, executors, providers, and `join_app` behavior.

## Reading the result correctly

This suite is a bounded model check. A passing Fixed case means the stated invariant holds for
the finite constants in that configuration; it does not establish an unbounded theorem. A Current
counterexample is evidence about a reachable source-like behavior, not automatically a production
failure under every deployment. Runtime probes use fakes or local resources unless their test name
explicitly exercises a real local transfer/executor path.

The v0.1 scope is frozen at the acceptance evidence above. Additional backend-specific audits or
new hypotheses belong in a later backlog and must not silently change the acceptance counts.

## Post-v0.1 extensions currently included

The repository has since kept the original acceptance gate reproducible while adding explicitly
tracked cross-layer refinements. The current gate is 678 TLC configurations and 443 runtime
entries. Recent extensions include provider-loss plus stage-out/monitoring correlation,
executor-result plus stage-out retry, non-blocking ThreadPool shutdown, and PoolExecutor map
timeout followed by advisory shutdown. These extensions are included in the 669-case gate and
their source/runtime evidence is recorded chronologically in `docs/progress-log.md`.

This remains a bounded validation package: it is not a line-by-line executable model of every
Parsl backend, and a passing Fixed configuration does not prove the unbounded implementation
correct. Source findings that are not yet modeled remain explicitly listed in the bug ledger and
limitations sections rather than being treated as silently covered.
